# KernelForge Dataset Card

## Overview

KernelForge's training dataset contains reference Triton kernels for five LLM-serving
operator families, each paired with a PyTorch reference implementation and a natural-language
explanation of the optimization.

## Construction

- **15 templates** (3 per operator family) × **20 shape configurations** each = **300 candidates**.
- Operator families: `quantized_matmul`, `attention`, `kv_cache`, `norm`, `rope`.
- Each candidate is a `(description, pytorch_reference, triton_kernel, explanation)` tuple
  generated by deterministic Python template functions in `data/templates/`.

## Verification

Every candidate is checked against its PyTorch reference by the subprocess-isolated
verification harness (`verification/`):

1. The reference `Model` and the candidate `ModelNew` are instantiated with identical weights.
2. Both run the same input tensor(s) on the same device.
3. Outputs are compared element-wise with tolerances `atol=0.01`, `rtol=0.01`.
4. A candidate passes only if the outputs match within tolerance.

The 12 incorrect `quantized_matmul` entries fail numerical comparison (max abs error 0.125
at `atol=0.01`). The 14 timeout/OOM entries exceed resource limits on the T4.

## Train / validation / test split

Split method: `split_by_template(seed=42)` — holds out one entire template per operator
family, so the test set contains shapes the model has never seen a kernel for.

Applied to the 274 GPU-verified entries:

| Partition | Entries | Templates |
|---|---|---|
| Train | 167 | 10 (2 per family) |
| Validation | 19 | same 10 as train |
| Test (held-out) | 88 | 5 (1 per family) |

Held-out templates: `attention__gqa_causal_prefill`, `kv_cache__decode_attention_gqa`,
`norm__layernorm`, `quantized_matmul__w8a16_perchannel`, `rope__fused_qk`.

Source: `training/run_20261118T004151Z/split_info.json`.

## Leakage finding and mitigation

An earlier 60-entry evaluation subset (used in the local fp32 baseline) had **30 of 60
entries overlapping with the training split** — 27 in train, 3 in val. The base-model
result (0/60 pass@1) is uncontaminated because the base model was not trained on any data,
but any fine-tuned evaluation on that subset would be biased.

The template-level split prevents this: the held-out test set consists entirely of templates
not present in the training or validation sets. No entry in the test partition shares a
template with any training entry. This is enforced by 12 integrity tests in
`tests/test_held_out_split.py` (all pass).

## Known limitations

- **Single GPU**: verified on a Tesla T4 (16 GB) only. Larger GPUs may pass the 26 rejected
  entries; smaller GPUs may reject more.
- **Small template count**: 15 templates across 5 families. Within a template, all 20 shape
  variants share the same kernel logic. The effective number of distinct kernels is 15, not 300.
- **4-bit baseline only**: the base-model evaluation uses 4-bit NF4 quantization on T4.
  Local fp32 and fp16 baselines exist but cover different entry subsets.
- **Forward-only**: all kernels implement forward passes. No backward/gradient kernels.
- **No model-generated content**: the dataset contains only hand-written reference kernels.
  Model outputs are evaluation artifacts, not training data.
